# Session Start Protocol

Apply at the first message of every session.

1. **Prime once, not twice.** If the first command is `/kickoff-consume`, it
   owns the priming — the kickoff block in the newest `HANDOFF.md` entry,
   `DECISIONS.md`, and the kickoff's read-list are loaded there; do not re-read
   them. In a session started
   without it, read `DECISIONS.md` yourself and confirm understanding if the
   session touches an area covered by a recorded decision. Either way: never
   contradict a decision without user approval.
2. **Draft fast.** Produce a first draft or proposal within the first few tool
   calls — don't over-explore before producing something the user can react to.
3. **Write artifacts to files, not chat.** Plans, analyses, and proposals must
   survive context compression. A file persists; a chat message does not.
4. **Plan-only unless asked.** When the user asked for a design, an analysis,
   or a proposal, don't jump to implementation.
